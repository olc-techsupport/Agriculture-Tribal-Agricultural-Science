# OLC/OST review checklist

## Governance and scope

- [ ] Confirm primary scope, contextual geographies, terminology, and responsible review authority.
- [ ] Approve or replace governance wording and decide which frameworks are locally applicable.
- [ ] Define whether the operational prototype and schema templates should remain in the public repository.
- [ ] Approve storage, access, retention, incident, location, withdrawal, and release procedures before using operational data.

## Scientific review

- [ ] Review proxy limitations, periods, geographies, units, thresholds, transformations, and missing-component behavior.
- [ ] Confirm that regional Census, county, climate-division, satellite, and USGS data are not represented as Nation-specific observations.
- [ ] Review the exploratory stress-index design and uncertainty.
- [ ] Verify all biological, agricultural, hydrologic, and management assumptions and citations.

## Instructional and release review

- [ ] OLC develops and approves the full curriculum from the learning stubs.
- [ ] Pilot each notebook with a learner new to coding.
- [ ] Run `python -m pytest` and the project validator in a clean environment.
- [ ] Commit notebooks without saved outputs.
- [ ] Complete NIFA award information, attribution, copyright, and citation metadata.
- [ ] Record the scope and date of approval without implying broader endorsement.
